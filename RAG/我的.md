## 2.html

### WebBaseLoader

~~~python
from langchain_community.document_loaders import WebBaseLoader

loader = WebBaseLoader("https://flask.palletsprojects.com/en/3.0.x/tutorial/layout/"
docs = loader.load()

for doc in docs:
    print(doc.page_content, doc.metadata)
~~~

> ⭐**解析**
>
> * **`loader = WebBaseLoader(...)`**
>   * 创建一个网页加载器，告诉它要读取哪个网页。此时只是准备好加载器。
> * **`docs = loader.load()`**
>   * 实际访问网页、提取文字，并将结果保存到 `docs`。它返回的是 **`Document` 对象组成的列表**，不是普通字符串。
> * 在 RAG 中，这属于**加载数据**这一步。之后通常还要进行文本切分、向量化和检索；这两行本身没有调用大模型。
>
> ⭐⭐**page_content打印的内容是什么？**
>
> * `page_content` 是从网页 HTML 中提取出的文字，不是经过整理的文章正文。
>
> * 可以把这个过程理解为：
>
>   ~~~
>   网页 HTML → 去掉 HTML 标签、提取文字 → page_content
>   ~~~
>
>

### BeautifulSoup

~~~python
from bs4 import BeautifulSoup

html_txt = ''
with open('./data/test.html', 'r') as f:
    for line in f.readlines():
        html_txt += line
        
soup = BeautifulSoup(html_txt, 'lxml')
code_content = soup.find_all('div', class_='highlight')

for ele in code_content:
    print(ele.text)
    print("+"*100)
~~~



> ⭐**你的代码可以分成四步理解。**
>
> **1. 读取本地 HTML**
>
> ```python
> html_txt = ''
> with open('./data/test.html', 'r') as f:
>     for line in f.readlines():
>         html_txt += line
> ```
>
> 逐行读取文件，再拼接成一个字符串。结合前面的编码问题，这里可以简化成：
>
> ```python
> with open('./data/test.html', 'r', encoding='utf-8') as f:
>     html_txt = f.read()
> ```
>
> **2. 解析 HTML**
>
> ```python
> soup = BeautifulSoup(html_txt, 'lxml')
> ```
>
> 让 BeautifulSoup 使用 `lxml` 解析器，把 HTML 解析成可以按标签查找的结构。
>
> **3. 筛选代码块**
>
> ```python
> code_content = soup.find_all('div', class_='highlight')
> ```
>
> 查找所有类似这样的元素：
>
> ```python
> <div class="highlight">
>     <pre>from flask import Flask</pre>
> </div>
> ```
>
> 这里并不是自动识别“哪些内容是代码”，而是**根据 HTML 的标签和 class 筛选**。在这个网页中，代码块使用了 `highlight` 类，所以能这样提取。
>
> **4. 打印每个代码块**
>
> ```python
> for ele in code_content:
>     print(ele.text)
>     print("+" * 100)
> ```
>
> `ele.text` 获取该元素内的文字；`"+" * 100` 打印 100 个加号，用来分隔不同代码块。
>
> 它们之间还有一个关系：**`BSHTMLLoader` 本身也使用 BeautifulSoup 来解析 HTML**，只是帮你封装了读取、提取文字和创建 `Document` 的步骤。你现在直接使用 BeautifulSoup，就能自行控制只提取哪些部分。

### 三者区别

这段代码是在**手动读取本地 HTML，并只提取其中的代码块**；前面的两个加载器`默认提取网页中的整体文字`，并`包装成 LangChain 文档`。

| 对比项       | 这段 BeautifulSoup 代码 | `BSHTMLLoader`   | `WebBaseLoader`  |
| ------------ | ----------------------- | ---------------- | ---------------- |
| 来源         | 本地 HTML 文件          | 本地 HTML 文件   | 在线网页         |
| 提取范围     | 指定的代码块            | 默认提取整体文字 | 默认提取整体文字 |
| 结果形式     | 当前代码直接打印字符串  | `Document` 列表  | `Document` 列表  |
| 来源等元数据 | 需要自己添加            | 加载器添加       | 加载器添加       |





## 3.pdf

### PyMuPDFLoader

~~~python
from langchain_community.document_loaders import PyMuPDFLoader

loader = PyMuPDFLoader('./data/zhidu_travel.pdf')
docs = loader.load()

for doc in docs:
    print(doc)
    print("="*100)
~~~

> ⭐⭐**这个是pdf里的文字都会提取出来吗，然后print(doc)默认就是打印doc.page_content吗？最后是按什么标准生成docs列表的？**
>
> 
>
> 可以分成三个问题理解。
>
> **1. PDF 里的文字都会提取出来吗？**
>
> 它会逐页提取 PDF 中**可以解析的文本**，但不保证提取到所有视觉上可见的文字：
>
> - 普通文字型 PDF：通常能直接提取文字。
> - 扫描件、图片里的文字：你这段代码默认没有开启 OCR，可能提取不到。
> - 复杂表格、多栏排版：可能提取出文字，但顺序和格式不一定与原页面一致。
>
> **2. `print(doc)` 等于 `print(doc.page_content)` 吗？**
>
> **不等于。** `print(doc)` 会调用文档对象的字符串表示，通常同时包含 `page_content` 和 `metadata`。[Document 源码](https://github.com/langchain-ai/langchain/blob/master/libs/core/langchain_core/documents/base.py)
>
> ```
> print(doc)               # 文本内容和元数据
> print(doc.page_content)  # 只打印文本内容
> print(doc.metadata)      # 只打印元数据，比如来源文件、页码
> ```
>
> 例如，`print(doc)` 的输出大致是：
>
> ```
> page_content='这是第一页的文字……' metadata={'source': './data/zhidu_travel.pdf', 'page': 0, ...}
> ```
>
> 而 `print(doc.page_content)` 只会输出：
>
> ```
> 这是第一页的文字……
> ```
>
> **3. `docs` 列表是按照什么标准生成的？**
>
> 你这种默认用法是**按照 PDF 的页来生成，每页对应一个 `Document`**，不是按段落、标题或固定字数切分。[PyMuPDFLoader 文档](https://reference.langchain.com/python/langchain-community/document_loaders/pdf/PyMuPDFLoader)
>
> 你截图里 `docs` 有 3 个元素，按默认分页方式，对应：
>
> ```
> docs
> ├── docs[0] → 第 1 页的 Document
> ├── docs[1] → 第 2 页的 Document
> └── docs[2] → 第 3 页的 Document
> ```
>
> 可以这样查看：
>
> ```
> for doc in docs:
>     print(f"第 {doc.metadata['page'] + 1} 页")  # page 从 0 开始
>     print(doc.page_content)
>     print("=" * 100)
> ```
>
> 注意：**`Document` 本身不一定代表一页**。这里一页一个对象，是 `PyMuPDFLoader` 的加载方式决定的；之后使用文本切分器，还可以把一页再拆成多个 `Document`。





### fitz

~~~python
import fitz

doc = fitz.open('./data/zhidu_travel.pdf')

table_data = []
text_data = []


doc_tables = {}
for idx, page in enumerate(doc):
    text = page.get_text()
    text_data.append(text)
    tabs = page.find_tables()
    for i,tab in enumerate(tabs):
        ds = tab.to_pandas()
        table_data.append(ds.to_markdown())
        
for tab in table_data:
    print(tab)
    print("="*100)
~~~

> ⭐**这代码具体做了什么？**
>
> ```python
> for idx, page in enumerate(doc):
> ```
>
> 逐页遍历 PDF，`idx` 是从 0 开始的页序号，`page` 是当前页面。
>
> ```python
> text = page.get_text()
> text_data.append(text)
> ```
>
> 提取当前页的文字，保存到 `text_data`。因此通常有：
>
> ```python
> text_data[0]  # 第 1 页文字
> text_data[1]  # 第 2 页文字
> ```
>
> 接下来单独处理表格：
>
> ```python
> tabs = page.find_tables()     # 检测当前页的表格
> 
> for i, tab in enumerate(tabs):
>     ds = tab.to_pandas()      # 表格转为 pandas DataFrame
>     table_data.append(ds.to_markdown())  # 再转为 Markdown 字符串
> ```
>
> 例如，保存的字符串可能是：
>
> ```python
> |    | 交通方式 | 报销标准 |
> |---:|:---------|:---------|
> |  0 | 火车     | 二等座   |
> |  1 | 飞机     | 经济舱   |
> ```
>
> **两个列表的划分标准不同：**
>
> ```python
> text_data  → 每页一个字符串
> table_data → 每个检测到的表格一个字符串
> docs       → 默认每页一个 Document
> ```
>
> 假设 PDF 有 3 页，第 1 页有 2 张表，第 2 页没有表，第 3 页有 1 张表，那么：
>
> ```python
> len(text_data)  # 3，对应 3 页
> len(table_data) # 3，对应 3 张表
> len(docs)      # 3，对应 3 页
> ```
>
> 虽然长度碰巧相同，代表的内容并不一样。而且你的 `table_data` 没有保存页码，无法直接看出每张表来自哪一页。
>
> 
>
> **还有两点需要注意：**
>
> - `page.get_text()` **可能已经包含表格里的文字**，所以 `text_data` 和 `table_data` 可能存在内容重复。
> - 第一段最后只遍历了 `table_data`，因此**正文虽然提取了，却没有打印出来**。`doc_tables = {}` 则没有在后续代码中使用。
>
> 如果你需要把表格保留成行列结构，第一段提供了明确的处理流程；⭐`如果是把 PDF 按页加载到 LangChain 中进行后续切分和检索，使用PyMuPDFLoader更方便。`

### 两者区别

主要区别是：**第一段直接使用 PyMuPDF，分别提取文字和表格；第二段使用 LangChain 封装的加载器，默认按页提取文字并生成 `Document` 列表。**

`fitz` 就是 PyMuPDF 的导入名称，所以两段代码底层使用的是同一个 PDF 处理库。

| 对比项       | 第一段：`fitz`                    | 第二段：`PyMuPDFLoader`              |
| ------------ | --------------------------------- | ------------------------------------ |
| 操作方式     | 自己逐页处理 PDF                  | 加载器封装处理过程                   |
| 普通文字     | 存在 `text_data` 中，每项是字符串 | 存在 `docs` 中，每项是 `Document`    |
| 表格         | 显式识别，转换为 Markdown 表格    | 当前代码未配置结构化表格提取         |
| 页码、来源   | 需要自己保存                      | 自动放在 `metadata` 中               |
| 最后打印什么 | 只打印提取到的表格                | 打印每页的文档对象，包含文字和元数据 |



> ⭐**import fitz和from langchain\_community.document\_loaders import PyMuPDFLoader是用的同一个底层库吗？**
>
> 
>
> 是的，**两者底层都使用 PyMuPDF**，只是调用层次不同：
>
> ```
> 你的代码 → fitz（PyMuPDF）→ PDF
> 你的代码 → PyMuPDFLoader → PyMuPDF → PDF
> ```
>
> - **`import fitz`**：直接使用 PyMuPDF，你自己控制逐页读取、文字提取、表格识别等操作。
> - **`PyMuPDFLoader`**：LangChain 对 PyMuPDF 的封装，帮你处理加载流程，并把结果整理成包含 `page_content` 和 `metadata` 的 `Document` 对象。
>
> 因此，**底层库相同，但输出形式和默认处理流程不同**。`fitz` 是 PyMuPDF 历史沿用的导入名称。

### Unstructured

**`unstructured`是一个Python库，主要用于处理`非结构化数据，如文本、PDF文档、电子邮件`等。这个库可以帮助你从这些非结构化的数据源中提取信息**

- pip install -i https://pypi.tuna.tsinghua.edu.cn/simple langchain_unstructured
- unstructured文档： https://docs.unstructured.io/open-source/core-functionality/partitioning





~~~python
from langchain_unstructured import UnstructuredLoader

loader = UnstructuredLoader('./data/zhidu_travel.pdf')
docs = loader.load()

for doc in docs:
    print(doc)
    print("="*100)
~~~



### UnstructuredLoader和PyMuPDFLoader的区别

最大的区别是：**你这两段代码中，`UnstructuredLoader` 默认按识别出的“文档元素”生成 `Document`，`PyMuPDFLoader` 默认按“页”生成 `Document`。**

两者返回的都是 `Document` 列表，所以后面的 `for doc in docs` 写法一样，但每个 `doc` 代表的内容不同。

| 对比项          | `UnstructuredLoader`           | `PyMuPDFLoader`  |
| --------------- | ------------------------------ | ---------------- |
| 使用的解析工具  | Unstructured                   | PyMuPDF          |
| 默认拆分单位    | 标题、正文段落、列表项等元素   | PDF 的每一页     |
| 一个 `Document` | 通常对应一个识别出的元素       | 对应一页文字     |
| 元数据          | 可能包含元素类别、页码、坐标等 | 包含来源、页码等 |
| 支持的文件范围  | PDF、Word、HTML 等多种格式     | 主要用于 PDF     |

这些默认行为可参见 [UnstructuredLoader 文档](https://reference.langchain.com/python/langchain-unstructured/document_loaders/UnstructuredLoader) 和 [PyMuPDFLoader 文档](https://reference.langchain.com/python/langchain-community/document_loaders/pdf/PyMuPDFLoader)。

**举个例子：同一页 PDF 包含这些内容**

```
差旅管理制度              ← 标题

员工出差需提前提交申请。   ← 正文段落

一、交通费用              ← 小标题

高铁按二等座标准报销。     ← 正文段落
```

用 `PyMuPDFLoader`，默认会得到 **1 个 Document**：

```
Document(
    page_content="差旅管理制度\n员工出差需提前提交申请。\n一、交通费用\n高铁按二等座标准报销。",
    metadata={"page": 0, ...}
)
```

用 `UnstructuredLoader`，**可能得到多个 Document**，例如：

```
Document(page_content="差旅管理制度",
         metadata={"category": "Title", ...})

Document(page_content="员工出差需提前提交申请。",
         metadata={"category": "NarrativeText", ...})

Document(page_content="一、交通费用",
         metadata={"category": "Title", ...})

Document(page_content="高铁按二等座标准报销。",
         metadata={"category": "NarrativeText", ...})
```

这是示意，具体数量和分类取决于页面内容、解析策略及识别结果，并不保证每个自然段都恰好对应一个元素。

你可以这样查看 Unstructured 实际拆出了什么：

```
for doc in docs:
    print("类别：", doc.metadata.get("category"))
    print("页码：", doc.metadata.get("page_number"))
    print("内容：", doc.page_content)
    print("=" * 100)
```

**因此，同一个 3 页 PDF，用 `PyMuPDFLoader` 默认得到 3 个文档；用 `UnstructuredLoader` 可能得到几十个文档。** 这不一定意味着提取的文字更多，往往只是拆分得更细。另外，使用 Unstructured 并不意味着表格、扫描文字一定能正确识别，效果还取决于解析配置。



> ⭐**我感觉UnstructuredLoader是逐行提取文字的**
>
> 
>
> **更准确的结论是：`PyMuPDFLoader` 默认按页拆分；`UnstructuredLoader` 按解析器识别出的元素拆分，这些元素可能是标题、段落，也可能只是单行文字。** 我这里还没有运行你环境中的 Unstructured，不能仅凭源 PDF 确定它实际拆出了哪些元素。

#### MSO_SHAPE_TYPE

~~~python
from pptx import Presentation
from pptx.enum.shapes import MSO_SHAPE_TYPE
ppt = Presentation('./data/test_ppt.pptx')

for slide_number, slide in enumerate(ppt.slides, start=1):
    print(f"Slide {slide_number}:")
    for shape in slide.shapes:
        if shape.has_text_frame:
            print(shape.text)
            
        if shape.has_table:
            table = shape.table 
            for row_idx, row in enumerate(table.rows):  
                for col_idx, cell in enumerate(row.cells): 
                    cell_text = cell.text  
                    print(f"Row {row_idx + 1}, Column {col_idx + 1}: {cell_text}")  
            
        if shape.shape_type == MSO_SHAPE_TYPE.PICTURE:
                    image = shape.image
                    image_filename = './data/test.jpg'
                    with open(image_filename, 'wb') as f:
                        f.write(image.blob)
~~~





#### 两者区别



核心区别是：**第一种把 PPT 内容整理成适合 LangChain 使用的文档；第二种直接访问 PPT 的页面、文本框、表格和图片，由你决定怎么处理。**

它们并不完全是两套独立的解析技术：Unstructured 的 `.pptx` 解析内部也使用了 `python-pptx`，再增加内容分类和整理逻辑。[Unstructured 源码](https://github.com/Unstructured-IO/unstructured/blob/main/unstructured/partition/pptx.py)

| 对比项           | `UnstructuredPowerPointLoader`             | `python-pptx`                        |
| ---------------- | ------------------------------------------ | ------------------------------------ |
| 抽象层级         | 较高：加载并整理文档内容                   | 较低：直接操作 PPT 对象              |
| 你这段代码的结果 | 返回 `list[Document]`                      | 打印文本、表格，并把图片写入文件     |
| 文本             | 自动提取，支持区分标题、正文等元素         | 用 `shape.text` 读取，分类规则自己写 |
| 表格             | 可提取为表格元素，保留结构取决于模式和参数 | 直接访问行、列、单元格               |
| 图片             | 你这段调用没有实现图片导出或图片内容识别   | `image.blob` 可以导出原始图片        |
| 页码等信息       | 取决于加载模式和元素元数据                 | 在逐页遍历时自行记录                 |
| 自定义程度       | 适合快速接入文档处理流程                   | 适合精细控制提取过程                 |

**1. 第一段的 `docs`，默认不是“一页一个 Document”**

你的代码：

```python
loader = UnstructuredPowerPointLoader("./data/test_ppt.pptx")
docs = loader.load()
```

默认使用 `mode="single"`，将提取出的内容合并成一个 `Document`。因此，即使 PPT 有很多页，通常也只得到一个文档对象。

其中：

```python
doc.page_content  # 提取出的文本
doc.metadata      # 来源等元数据
```

如果希望区分标题、段落、表格等元素，可以使用：

```python
loader = UnstructuredPowerPointLoader(
    "./data/test_ppt.pptx",
    mode="elements",
)

docs = loader.load()

for doc in docs:
    print(doc.page_content)
    print(doc.metadata)
```

此时**一个元素对应一个 Document，也不等于一页一个 Document**。元素元数据可以包含类别、页码等信息。[LangChain 文档](https://reference.langchain.com/python/langchain-community/document_loaders/powerpoint/UnstructuredPowerPointLoader)

**2. 第二段是在自己编写提取规则**

你明确规定了三类处理：

```python
if shape.has_text_frame:
    # 读取文本框文字

if shape.has_table:
    # 按行、列读取单元格文字

if shape.shape_type == MSO_SHAPE_TYPE.PICTURE:
    # 导出图片文件
```

这种方式可以更方便地保留“第几页、哪个表格、第几行、第几列”等信息。但你目前只是 `print()`，**并没有把内容收集成供后续检索使用的文档列表**。

另外，当前循环只检查页面顶层的形状。若文本、图片位于组合形状中，需要递归遍历组合内部的 `shape.shapes`。[python-pptx 形状文档](https://python-pptx.readthedocs.io/en/stable/api/shapes.html)

**3. 你保存图片的代码有两个需要注意的地方**

```python
image_filename = "./data/test.jpg"
```

- 每张图片都使用相同文件名，后面的图片会覆盖前面的图片。
- `image.blob` 是原始图片数据；把扩展名写成 `.jpg`，不会把 PNG 等格式转换为 JPEG。

可以给图片使用独立文件名，并保留真实扩展名：

```python
# 配合：for shape_idx, shape in enumerate(slide.shapes, start=1):
image = shape.image
image_filename = (
    f"./data/slide_{slide_number}_image_{shape_idx}.{image.ext}"
)

with open(image_filename, "wb") as f:
    f.write(image.blob)
```

`blob` 和 `ext` 分别提供图片的二进制数据与相应扩展名。[python-pptx 文档](https://python-pptx.readthedocs.io/en/latest/api/image.html)

**导出图片不等于识别图片内容。** 第二段不会自动读取截图中的文字，也不会理解图片中的流程图；这需要额外接入 OCR 或视觉模型。

⭐`对于你的 RAG 学习场景：`

- **快速实现 PPT 文本检索**：第一种更省代码，可以接着做文本切分、向量化和检索。
- **需要保留页面、单元格位置，或单独处理图片**：第二种更灵活，再把提取结果封装成 LangChain 的 `Document`。
- **需要理解截图、图表、流程图**：在内容提取之外，增加图片识别或视觉理解步骤。

另外，第一种的 `load()` 只负责加载文档，**不会自动完成向量化或建立向量数据库**。

### 代码

~~~python
import numpy as np
from langchain_community.document_loaders import PyMuPDFLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_experimental.text_splitter import SemanticChunker

doc_path = './data/zhidu_travel.pdf'
loader = PyMuPDFLoader(doc_path)
docs = loader.load()
data = []
for doc in docs:
    data += doc.page_content.split('。')

word_nums = [len(txt) for txt in data if len(txt) != 0]
np.mean(word_nums)
np.min(word_nums)
np.max(word_nums)
np.percentile(word_nums, q=95)
~~~

> **代码解析**
>
> 
>
> 这段代码是在**读取 PDF，按中文句号拆分文本，再统计每段文本的字符数分布**，可以用来了解文档长度，为后续分块大小提供参考。
>
> 逐步来看：
>
> ```
> loader = PyMuPDFLoader('./data/zhidu_travel.pdf')
> docs = loader.load()
> ```
>
> 读取 PDF。在这个用法中，`docs` 通常是按页组织的文档列表，`doc.page_content` 是对应页的文本。
>
> ```
> data = []
> for doc in docs:
>     data += doc.page_content.split('。')
> ```
>
> 把每页文本按中文句号 `。` 拆开，再汇总到 `data`。例如：
>
> ```
> "住宿费凭据报销。交通费每天80元。".split('。')
> # ['住宿费凭据报销', '交通费每天80元', '']
> ```
>
> 这里只按句号拆分，并没有真正理解句子；跨页的句子也不会自动拼接。
>
> ```
> word_nums = [len(txt) for txt in data if len(txt) != 0]
> ```
>
> 计算每个非空片段的长度。**这里统计的是字符数，不是词数，也不是 token 数**；空格、换行、数字和标点也计入长度。
>
> 接下来四项统计：
>
> | 代码                             | 含义                   |
> | -------------------------------- | ---------------------- |
> | `np.mean(word_nums)`             | 平均字符数             |
> | `np.min(word_nums)`              | 最短片段的字符数       |
> | `np.max(word_nums)`              | 最长片段的字符数       |
> | `np.percentile(word_nums, q=95)` | 字符数的第 95 百分位数 |
>
> 例如，第 95 百分位数是 `200`，可以理解为：**大约 95% 的片段长度不超过 200 个字符**。百分位数可能通过插值计算，因此结果不一定是整数。
>
> 
>
> **有两个细节：**
>
> - `RecursiveCharacterTextSplitter` 和 `SemanticChunker` 只是导入了，这段代码没有使用它们。
> - 在 notebook 同一个单元格中，通常只自动显示最后一个表达式的结果。想看到全部统计值，可以写：
>
> ```
> print("平均字符数：", np.mean(word_nums))
> print("最少字符数：", np.min(word_nums))
> print("最多字符数：", np.max(word_nums))
> print("95%分位字符数：", np.percentile(word_nums, q=95))
> ```



> **np.percentile(word\_nums, q=95) 是什么意思？**
>
> 
>
> `np.percentile(word_nums, q=95)` 是计算 `word_nums` 的**第 95 百分位数**。
>
> 在你的代码中，`word_nums` 保存了各个文本片段的字符数。假设：
>
> ```
> np.percentile(word_nums, q=95)
> # 200.0
> ```
>
> 可以理解为：
>
> > 大约 95% 的文本片段不超过 200 个字符，剩下约 5% 更长。

### 和上述PyMuPDFLoader的区别



**两段代码读取 PDF 的方式完全相同，区别在于读取后做什么。**

```

打印的是整个 `Document` 对象的表示，通常包含 `page_content` 和 `metadata`。如果只想看正文，可以改为：

## 8.递归文本分块：RecursiveCharacterTextSplitter

~~~python
from langchain_community.document_loaders import PyMuPDFLoader
doc_path = './data/zhidu_travel.pdf'
loader = PyMuPDFLoader(doc_path)

r_spliter = RecursiveCharacterTextSplitter(
    chunk_size=128,
    chunk_overlap=30,
    separators=[
        "\n\n",
        "\n",
        ".",
        "．",  # 全角句点
        "。",  # 中文句号
        ",",
        "，",  # 中文逗号
        "、",  # 顿号
    ],
)

split_docs = loader.load_and_split(r_spliter)

print(split_docs[0].page_content)
print(split_docs[1].page_content)

docs = loader.load()
split_docs = r_spliter.split_documents(docs)
print(split_docs[0].page_content)
~~~



> ⭐**代码解析**
>
> 
>
> 这段代码的作用是：**先定义文本切分规则，再读取文档，并按照规则把文档切成小块**，方便后续做 RAG 检索。
>
> **1. `r_spliter` 是一个文本切分器**
>
> ```
> r_spliter = RecursiveCharacterTextSplitter(
>     chunk_size=128,
>     chunk_overlap=30,
>     separators=[...],
> )
> ```
>
> 各参数的含义：
>
> | 参数               | 含义                                                         |
> | ------------------ | ------------------------------------------------------------ |
> | `chunk_size=128`   | 每块的目标最大长度为 128 个字符，默认按 `len()` 计数，不是 token 数 |
> | `chunk_overlap=30` | 相邻块之间目标重叠 30 个字符，帮助保留上下文；实际不一定恰好重叠 30 个 |
> | `separators=[...]` | 按优先级尝试的切分位置                                       |
>
> “递归切分”可以理解为：先尝试按 `"\n\n"`（段落）切，某段仍太长，就继续尝试 `"\n"`（换行），再尝试句号、逗号等。短片段还会被合并成合适大小的块，并非每遇到一个标点都单独生成一块。[官方切分说明](https://docs.langchain.com/oss/python/integrations/splitters/recursive_text_splitter)
>
> **2. `loader.load_and_split(r_spliter)` 是“加载 + 切分”**
>
> `loader` 是你前面创建的**文档加载器对象**，具体读取 PDF、文本文件还是网页，要看它的类型。
>
> ```
> split_docs = loader.load_and_split(r_spliter)
> ```
>
> 在 LangChain 标准加载器中，基本等价于：
>
> ```
> # 第一步：读取数据，得到 Document 列表
> docs = loader.load()
> 
> # 第二步：使用你定义的切分器，切成更小的 Document
> split_docs = r_spliter.split_documents(docs)
> ```
>
> 这里传入的 `r_spliter` 就是在告诉加载器：**“加载完成后，用这个切分器处理文档。”**
>
> 返回的 `split_docs` 是 `Document` 对象列表，不只是字符串。可以这样查看：
>
> ```
> print(len(split_docs))              # 切出了多少块
> print(split_docs[0].page_content)   # 第一块的文本
> print(split_docs[0].metadata)       # 来源、页码等信息，具体取决于加载器
> ```
>
> 当前官方文档已将 `load_and_split` 标注为应视为`弃用`，因此新代码更建议使用上面的两步写法，过程也更清楚。[加载器 API 文档](https://reference.langchain.com/python/langchain-core/document_loaders/base/BaseLoader)
>
> **3. 你的分隔符列表可以补一个 `""`**
>
> ```
> separators=["\n\n", "\n", ".", "．", "。", ",", "，", "、", ""]
> ```
>
> 末尾的空字符串表示：如果文本太长，而且没有可用的分隔符，最后就按字符切分。你原来的列表没有这个兜底，所以某些块可能超过 128 个字符。



> ⭐**”因此新代码更建议使用上面的两步写  “是什么意思？**
>
> 
>
> 意思是：把“读取 PDF”和“切分文本”**分成两行代码来写**。
>
> 原来一行完成：
>
> ```
> split_docs = loader.load_and_split(r_spliter)
> ```
>
> 建议改成：
>
> ```
> # 第一步：读取 PDF
> docs = loader.load()
> 
> # 第二步：切分读取到的文档
> split_docs = r_spliter.split_documents(docs)
> ```
>
> 两种写法完成的事情基本相同。建议分开写，是因为 `load_and_split()` 已被官方标记为应视为弃用；分别调用 `.load()` 和 `.split_documents()` 也更方便查看切分前后的内容。
>
> **不是说你的原代码现在不能运行，而是新写代码时优先使用拆开的写法。**
