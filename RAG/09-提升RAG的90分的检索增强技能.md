## 检索的两大形态：稀疏 vs 稠密

<a id="topic-006"></a>

### 稀疏检索

- 稀疏检索（sparse retriever）

- 稀疏检索
  - 关键词匹配的拓展
  - 根据词频等信息，依赖于统计学方法，来评估文档与查询之间的相关性
  - 常用算法：TF-IDF，BM25

<!-- PDF 第 7 页 -->
<a id="page-007"></a>


- 稀疏检索（sparse retriever）

度量词语在文档中的重要性

![图示](./images/09-page-007-figure-01.png)

TF-IDF

TF-IDF与一个词在文档中的出现次数成正比，与该词在整个语言中的出现次数成反比

特点：计算简单，只考虑词频，不关注顺序和上下文，词频来衡量文章中的一个词的重要性不够全面

<!-- PDF 第 8 页 -->
<a id="page-008"></a>


- 稀疏检索（sparse retriever）

![图示](./images/09-page-008-figure-01.png)

<a id="page-009"></a>


- 稀疏检索（sparse retriever）

- 稀疏检索缺点--
  - 考虑词频，不关注顺序和上下文
  - 男朋友/送/的/礼物
  - 送/男朋友/的/礼物
  - 白/衬衫 /灰/裤子

### 稠密检索

- 稠密检索 （dense retriever ）

- 稠密检索
  - 语义检索：将文本转换为embedding向量
  - 基于BERT架构：GTE/ BGE
  - 信息压缩：将语义信息压缩到固定长度数组里，存在信息丢失的风险

### 子问题查询与拆解

- 查询增强：子问题查询

问题复杂：问题描述复杂，包含多个语义的问题，直接用复杂问题进行向量化检索可能会导致部分问题丢失，影响检索的性能

问题拆解：利用大语言模型将问题拆解成子问题，每个子问题都生成检索上下文，可以根据合并后的总的上下文去回答，也可以每个上下文独立去回答

![图示](./images/09-page-020-figure-01.png)

<!-- PDF 第 21 页 -->
<a id="page-021"></a>


- 查询增强：子问题查询-子问题拆解

Your purpose is to help answer a complex user question by generating a list of sub questions that can be answered by the tools.

These are the guidelines you consider when completing your task:

- Be as specific as possible
- The sub questions should be relevant to the user question
- The sub questions should be answerable by the tools provided
- You can generate multiple sub questions for each tool
- Tools must be specified by their name, not their description
- You don't need to use a tool if you don't think it's relevant

### Take a Step Back

- 查询增强：Take a Step Back

![图示](./images/09-page-024-figure-01.png)

问题太细：用户提出的问题往往包含大量细节，可能导致检索时忽略了关键的信息，降低检索性能

问题抽象化：将用户的具体问题转化为一个更高层次的抽象问题，一个更广泛的问题，关注于高级概念或原则，从而帮助模型更有效地进行信息检索

### 重排序与BGE Reranker

- 检索增强：重排序rerank

- 重排序
  - 检索增强：生成多个基于相似度查询到的相似文档
  - 需要精简：检索太多文档增加LLM生成准确答案难度，生成速度慢，引入干扰
  - 文档重排序：使与用户输入问题的更相关、更准确的文档分块排名更靠前
  - Post-Retrieval： 检索后增强

- 检索增强：重排序rerank

- 重排序

  - 常用模型：Cohere Rerank模型 /bge-reranker-large模型

### 迭代检索增强生成

- 系统性查询增强：迭代检索增强生成

- 迭代检索增强
  - 单步增强变多次迭代增强，每次迭代都是一次完整的RAG过程，生成答案
  - 每次迭代生成的答案中都可能包含了回答问题的额外信息，这些信息有助于检索更准确的上下文
  - Modular RAG： 系统性增强

<!-- PDF 第 39 页 -->
<a id="page-039"></a>


- 系统性查询增强：迭代检索增强生成

- 迭代1：给定一个问题，检索到上下文信息
- 迭代1：模型针对问题和上下文信息，生成可能正确的答案
- 迭代2：将生成可能正确的答案再合并到问题，做为新的问题，去检索上下文问题
- 迭代2：模型再次针对问题和新的上下文信息，生成答案

## 总结和展望

<a id="topic-045"></a>

### 检索增强技术回顾

- 总结

- RAG检索增强
  - RAG设计框架：Navie RAG、Advanced RAG和Modular RAG
  - 检索形态：基于文本匹配统计的稀疏检索（TF-IDF和BM25），基于语义embedding的稠密检索（BGE/GTE）
  - 用户问题的多样性：引出检索增强技术

<!-- PDF 第 46 页 -->
<a id="page-046"></a>


- 总结

- 查询增强
  - 目的：从用户问题出发对查询进行转换，
  - Query2Doc、HyDE：查询生成假设性的文档，来增加额外的信息来增加上下文的匹配
  - 查询改写、子问题查询：对问题进行重写，对复杂问题进行拆解
  - Take step back：对问题进行抽象化处理，去除无畏的细节，增加匹配度

<!-- PDF 第 47 页 -->
<a id="page-047"></a>


- 总结

- 多索引检索
  - 父子检索：从文档的大小颗粒度来建立索引，用小文档来检索，返回大文档用做上下文
  - 总结检索：从文档的信息摘要来建立索引，用大文档的摘要来检索，返回大文档用做上下文
  - 假设性问题检索：从问题这一个颗粒度来建立索引，实现问题和问题的匹配检索，用大文档逆向衍生出来的不同角度的假设性问题来检索，返回大文档用做上下文

<!-- PDF 第 48 页 -->
<a id="page-048"></a>


- 总结

- 检索后增强
  - 融合检索：综合基于关键词匹配的稀疏检索和基于语义的稠密检索的特点，重点是对于两种检索方法得到的文档，根据加权倒数排名来计算融合分数，以此来确定融合后的文档的排序
  - 重排序rerank：对于检索到众多文档，利用模型的能力来评分，评分越高和问题越相关，rerank是在基于相似度检索的基础上，从另外一种维度来对检索文档进行精排

<!-- PDF 第 49 页 -->
<a id="page-049"></a>


- 总结

- 模块化系统增强
  - 迭代检索增强生成：从迭代的角度利用每次迭代的生成的答案来进行增加检索的相关性，以此来提升检索的性能
  - Self-RAG：RAG新范式，将评判步骤添加到RAG的流程中，使得可以根据RAG流程每个步骤的结果的好坏来动态的选择优化策略
